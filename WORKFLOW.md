# Единый воркфлоу игровых проектов

Один и тот же процесс во всех репозиториях, чтобы переключаться между играми без
переучивания, а хаб мог считать прогресс одним и тем же способом.

## Структура репозитория

```
<repo>/
  CLAUDE.md            # рабочие заметки для Claude: layout, verification loop, process, conventions
  README.md            # что за игра, как запустить, где лежит что
  project.yaml         # метаданные для хаба: фаза, слоган, что дальше
  docs/
    GDD.md             # видение: пилларсы, core loop, тон, non-goals
    DESIGN.md          # журнал решений (дата, вопрос, варианты, решение)
    plan.yaml          # план: вехи и задачи — ЕДИНСТВЕННЫЙ источник плана
    PLAN.md            # сгенерирован из plan.yaml, руками не править
    specs/             # спеки на систему: что и почему, не как
  tools/
    sync_plan.py       # plan.yaml -> PLAN.md + метки, вехи и issues на GitHub
  .claude/
    skills/next-task   # предложить задачу из открытых issues
    skills/sync-plan   # прогнать sync_plan.py после правки plan.yaml
    skills/playtest    # оформить отчёт о плейтесте в issue и журнал решений
  <godot project>/     # либо в корне, либо в подпапке с именем игры
```

## Трекер задач: GitHub Issues

- План живёт в `docs/plan.yaml`. Вехи = milestones, задачи = issues. `python3 tools/sync_plan.py --github`
  идемпотентно создаёт недостающее. Закрываются issues на GitHub, не в yaml.
- Метки одни и те же во всех репо:
  - `type: code | 3d | art | design | vfx | ui | audio | release`
  - `size: S | M | L | XL` (полдня, день, два дня, три дня)
  - `status: needs decision | in progress | blocked | needs playtest`
  - `owner: artemii | claude | both`
- Задача атомарна: не делится на меньшие. Порядок задаёт веха и блокеры в описании.

## Цикл работы над задачей

1. Взять issue. Если нужно дизайн-решение, Claude пишет в issue короткий бриф: вопрос,
   2-3 варианта, рекомендация, метка `status: needs decision`. Ждёт решения.
2. Реализация на `main` небольшими коммитами. Сообщение коммита ссылается на issue (`#12`).
   Трейлер `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Пуш в конце сессии.
3. Когда играбельно: метка `status: needs playtest`, комментарий что пробовать и какие дебаг-инструменты помогут.
4. Плейтест. Замечания в issue, итерации. Issue закрывает Артемий.
5. Definition of done: автотест зелёный, скриншот или замер в issue, решения записаны в `docs/DESIGN.md`.

## Дизайн-документы

- `GDD.md` короткий и редко меняется. Спеки в `docs/specs/<system>.md` по шаблону: цель,
  поведение, данные, крайние случаи, задачи. Тюнинг-числа живут в ресурсах Godot, не в спеках.
- Любое решение, принятое в чате, в тот же день попадает в журнал `docs/DESIGN.md`.

## Хаб

- `gamedev-hub/projects.yaml` знает все проекты. Дашборд пересобирается GitHub Actions
  раз в сутки и вручную: таблица статусов, прогресс по issues, календарь активности по дням и играм.
- Фазу проекта хаб берёт из `project.yaml` в корне репозитория игры, если он есть, иначе из реестра.
- Новый проект: `python3 tools/new_project.py <Name> --tagline "..."` создаёт репозиторий из
  `template/`, заводит метки и добавляет запись в реестр.
